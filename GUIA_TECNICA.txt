1. ARQUITECTURA GENERAL
------------------------------------------------------------------------
- Frontend: Angular (Motor de renderizado en Canvas API).
- Backend: Java Spring Boot (Motor de sincronización WebSockets).
- Bases de Datos: 
    * MySQL: Persistencia de usuarios, niveles y créditos.
    * MongoDB: Historial de partidas y analíticas de juego.

2. LÓGICA DE COMUNICACIÓN (WebSockets)
------------------------------------------------------------------------
El servidor (GameWebSocketHandler.java) actúa como el cerebro de la red:
- Gestiona salas (Rooms) y jugadores (Players).
- Si un jugador se desconecta, se convierte automáticamente en BOT.
- Valida turnos y lanza eventos globales (como la Ruleta de Habilidades).
- Sincronización: Se usan timestamps del servidor para mitigar el lag.

3. LÓGICA DE JUEGO (GameService.ts)
------------------------------------------------------------------------
- Facciones: Cada facción tiene modificadores de daño y coste de munición.
- Habilidades: Sistema de efectos de estado (statusEffects) que alteran
  el comportamiento de los misiles (sigilo, velocidad, daño nuclear).
- Colisiones: Calculadas mediante distancia euclidiana entre coordenadas.

4. PERSISTENCIA DUAL
------------------------------------------------------------------------
- MySQL (JPA): Datos transaccionales que requieren consistencia (Tienda).
- MongoDB: Datos masivos y no estructurados (Estadísticas de batalla).

5. MANTENIMIENTO
------------------------------------------------------------------------
- El sistema es escalable. Para añadir nuevas armas o facciones, basta con 
  actualizar los enumerados en GameService y las validaciones en el Backend.
