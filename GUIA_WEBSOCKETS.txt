========================================================================
             PROTOCOLO DE COMUNICACIÓN (WEBSOCKETS)
========================================================================

NOTA: Para una visión detallada con diagramas de flujo y payloads JSON,
consulte la sección 4 de GUIA_TECNICA.md.

1. ESPECIFICACIÓN TÉCNICA
------------------------------------------------------------------------
- Endpoint: ws://localhost:8080/game
- Formato: JSON (UTF-8)
- Librería Backend: Spring WebSocket (TextWebSocketHandler)
- Librería Frontend: Native WebSocket API + RxJS Subjects

2. ESTRUCTURA DE LOS PAQUETES
------------------------------------------------------------------------
Cada mensaje enviado o recibido sigue este esquema:
{
  "type": "string", // Identificador de la acción
  "data": "object"  // Datos asociados (Payload)
}

3. EVENTOS CRÍTICOS
------------------------------------------------------------------------
- "launch-missile": Sincroniza el disparo. Contiene targetX, targetY y cityId.
- "turn-advanced": Notifica el cambio de turno y actualiza el contador global.
- "skill-roulette": Generado por el servidor cada 4 turnos. Asigna poderes.
- "player-became-bot": Se dispara automáticamente al cerrarse un socket.

4. SISTEMA DE RESILIENCIA
------------------------------------------------------------------------
- Heartbeat: Sistema de Ping/Pong interno para mantener sesiones activas.
- Auto-Reconnect: El cliente intenta reconectar cada 2 segundos tras caída.
- State Sync: Al reconectar, el servidor envía un 'room-update' con el
  estado actual de todos los jugadores (vida, munición, posición).
